## 二、呼吸灯（PA1 / TIM2_CH2）

### 2.1 定时器配置

| 项目 | 值 | 说明 |
|---|---|---|
| Clock Source | Internal Clock | 内部时钟 |
| Channel 2 | PWM Generation CH2 | PA1 |
| PSC | 71 | 72 MHz / (71+1) = **1 MHz** 计数频率 |
| ARR (Counter Period) | 999 | 1 MHz / (999+1) = **1 kHz** PWM |
| Pulse | 0 | 上电占空比 0 |
| Mode | PWM mode 1 | |
| CH Polarity | High | 高电平有效 |

### 2.2 亮度控制

- 占空比量程 0~1000（`BSP_PWM_DUTY_MAX`），亮度 0~100% 映射为 `CCR = percent × 10`。
- 呼吸算法：把周期分成两半，前半段亮度 `0 → 100`，后半段 `100 → 0`（三角波），每 10 ms 更新一次 CCR。
- 呼吸周期可配 **1000~10000 ms**，默认 4000 ms。4 s 周期下亮度台阶约 2.5%，肉眼平滑。
- **呼吸模式只驱动外接 PWM 灯（PA1）**，板载灯（PC13）保持用户设定的 ON/OFF 不动
  —— 两个灯可以各自呈现不同状态（板载灯常亮当电源指示、外接灯呼吸）。

### 2.3 接线（重要）

PA1 输出的是 **高电平有效** 的 PWM：

```
PA1 ──[限流电阻 220Ω~1kΩ]── LED 正极 ── LED 负极 ── GND
```

如果接成"LED 正极接 3V3、负极接 PA1"（低电平点亮），亮度会反过来（越暗越亮）。改接法或把
`BSP_PWM_SetPercent()` 里的占空比取反即可。

## 三、参数持久化（SAVE 后重新上电仍有效）

### 3.1 存储位置

- 内部 Flash **最后一页** `0x0800FC00`（page 63，1 KB），与程序区不重叠。
- 数据结构 20 字节：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | magic | `0xA5A55A5A` |
| 4 | version | `0x0102`（v1.2） |
| 6 | led_mode | 0=MANUAL 1=BLINK 2=FAST 3=BREATH |
| 7 | led_state | 0=OFF 1=ON |
| 8 | blink_period_ms | 100~5000 |
| 10 | fast_period_ms | 100~5000 |
| 12 | breath_period_ms | 1000~10000 |
| 14 | menu_start_page | 保留 |
| 15 | reserved | 保留 |
| 16 | checksum | 覆盖 0~15 字节的 16 位补码和 |
| 18 | reserved2 | 填充，保证 4 字节对齐 |

### 3.2 保存与恢复流程

```
串口 SAVE ──► 钳位参数 → 填 magic/version → 重算校验和 → 擦页 → 按字写入(5 个 word)
上电      ──► 读参数页 → 校验 magic + version + 5 个字段范围 + 校验和
                 ├─ 全部通过 → 采用
                 └─ 任一失败 → 载入默认值（不擦除 Flash，不会死机）
```

- 版本号变更后（v1.1 → v1.2）旧参数会被判为无效并回到默认值，这是预期行为。
- 页面里调完参数只改 RAM，**必须发一次 `SAVE`** 才会写 Flash。
- `RESET` 恢复默认值（不写 Flash，需要断电保持请再发 `SAVE`）。

## 四、非法参数与快速命令的防护

| 场景 | 处理方式 | 结果 |
|---|---|---|
| `SET MODE 9` / `SET MODE abc` | `strtol` + 全串校验 + 范围 0~3 | `ERROR: MODE RANGE`，状态不变 |
| `SET PERIOD 99999` | 按当前模式取范围（闪烁 100~5000 / 呼吸 1000~10000） | `ERROR: PERIOD RANGE` |
| `SET PERIOD -5` | 负数低于下限 | `ERROR: PERIOD RANGE` |
| 超长行（>63 字节） | 标记 `too_long`，整行丢弃 | `ERROR: COMMAND TOO LONG` |
| 一次粘贴 10+ 条命令 | 9 条行队列缓冲，超出部分丢弃并计数 | 前面的正常执行，最后 `ERROR: COMMAND QUEUE FULL` |
| 串口溢出 ORE | `HAL_UART_ErrorCallback` → 清标志 → 重挂接收 | 自动恢复，不需要复位 |
| Flash 参数被写坏 | magic/版本/范围/校验和任一不过 → 默认值 | 正常启动 |
| 除零 / 数组越界 | 周期钳位 ≥1、模式名查表前判上界 | 不会 HardFault |

> 说明：`SET PERIOD` 的合法范围随当前模式变化；呼吸模式下必须 ≥1000 ms，否则报错而不是静默接受。

## 五、命令与菜单

| 命令 | 说明 |
|---|---|
| `HELP` | 命令列表 |
| `LED ON\|OFF\|TOGGLE` | 手动控制（会切到 MANUAL 模式） |
| `STATUS` | 单行状态 |
| `GET STATUS` | 完整状态（模式/亮度/周期/计数/最后错误） |
| `GET PARAM` | 读出 Flash 中的参数（含 BREATH PERIOD） |
| `SET MODE 0/1/2/3` | 0=MANUAL 1=BLINK 2=FAST 3=BREATH |
| `SET PERIOD N` | 按当前模式设周期：闪烁 100~5000，呼吸 1000~10000 |
| `SET LED ON\|OFF` | 设 LED 状态（会切到 MANUAL 模式） |
| `MAIN ON\|OFF\|TOGGLE` | **只改板载灯，不改变模式**（呼吸/闪烁中也能用） |
| `SAVE` | 参数写 Flash（掉电保持） |
| `RESET` | 恢复默认参数 |

## 六、验收自测步骤

1. 烧录 `MDK-ARM/test_led/test_led.hex`，复位。
2. 串口发 `SET MODE 3` → 返回 `OK MODE=BREATH`，PA1 外接 LED 开始呼吸，板载 LED 跟着亮灭。
3. 发 `SET PERIOD 8000` → 呼吸变慢；发 `SET PERIOD 500` → 返回 `ERROR: PERIOD RANGE`（呼吸模式下限 1000）。
4. 发 `SET PERIOD 2000` 后发 `SAVE` → 返回 `OK SAVE`。
5. **断电再上电** → 发 `GET PARAM` 应看到 `MODE: 3 (BREATH)`、`BREATH PERIOD: 2000ms`；
   不发命令也能看到呼吸灯按 2 s 周期工作（说明模式也被恢复了）。
6. 发 `SET MODE 9`、`SET PERIOD abc`、70 个字符再回车 → 均应返回错误且系统继续工作。
7. 用脚本以 1 ms 间隔连续发 2000 字节，再发 `HELP` → 仍能正常响应（不会假死）。
8. 快速粘贴 10 条 `LED TOGGLE` → LED 状态最终正确，串口有响应，系统不卡死。
9. **两个灯独立演示**：`SET MODE 3` 后发 `MAIN ON` → 板载灯常亮、外接灯呼吸；`MAIN OFF` → 板载灯灭、外接灯继续呼吸。

## 七、已知限制

1. **参数只在上电时加载**，运行中改参数不影响已加载的副本（下次上电生效）。
2. 菜单里调参数不自动保存，需要 `SAVE`（避免频繁擦写 Flash）。
3. 呼吸模式只驱动外接 PWM 灯；若需要"板载灯闪 + 外接灯呼吸"同时进行，需要再做双通道改造。
4. 串口发送仍是阻塞式（`HAL_UART_Transmit`，超时 1 s）；正常命令回包 < 12 ms，不影响按键扫描。
5. OLED 全屏刷新（清屏 + 一页页写）约 8~10 ms，发生在 100 ms 任务里，偶发会让按键响应延迟一两拍。
